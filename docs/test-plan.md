# AI 看护系统门口看护器 V1 测试计划

## 1. 测试目标

本测试计划用于验证门口看护器 V1 是否满足以下目标：

- 设备能够稳定连接阿里云后端并通过健康检查
- 设备能够基于 PIR 与语音 VAD 正确触发事件采集
- 设备能够正确上传门口事件及相关附件
- 云端能够生成事件记录并返回分析结果
- 设备能够根据云端结果完成语音播报
- 系统能够在边界条件和异常条件下保持可预期行为
- 需求文档、接口文档与实际实现具备一致性

## 2. 测试范围

### 2.1 范围内

- 健康检查接口测试
- PIR 触发测试
- VAD 触发测试
- 设备事件上传测试
- 结果查询测试
- 语音播报测试
- 基本鉴权测试
- 文件格式、字段校验、状态流转测试
- 设备弱网与重试相关测试
- 验收标准验证

### 2.2 范围外

- App 或 Web 前端完整功能测试
- 大规模压测与容量极限测试
- OTA 升级测试
- 多设备管理平台测试
- 长时间录像与回放测试

## 3. 测试环境

### 3.1 设备环境

- Seeed XIAO Sense 开发板
- 摄像头模块，基于 XIAO Sense 当前可用方案，具体型号待确认
- 麦克风模块，基于 XIAO Sense 当前可用方案，具体输入链路待确认
- Seeed Mini PIR motion sensor
- MAX98357A + 3W 喇叭
- WiFi 网络，可模拟正常、弱网和断网环境

### 3.2 后端环境

- 阿里云测试环境
- HTTPS 可访问的 V1 API
- 可查看请求日志、错误日志与分析任务状态
- 对象存储、数据库、消息系统具体组件：待确认

### 3.3 测试数据

- 正常图像样本
- 模糊、过暗、过亮图像样本
- 合法与非法音频样本
- 各类事件类型样本
- 空字段、超长字段、非法格式字段样本
- 不同语音音量和背景噪声样本

## 7. 验收标准

### 7.1 功能验收

- 健康检查接口可稳定返回服务状态
- PIR 与 VAD 触发均可稳定进入采集流程
- 设备可成功上传最小必填事件
- 上传成功后可获得唯一 `event_id`
- 结果接口可返回 `queued`、`processing`、`done`、`failed` 等状态
- 分析完成后结果中至少包含 `status`、`risk_level`、`summary`、`voice_broadcast_text`
- 设备可通过 MAX98357A + 3W 喇叭完成语音播报

### 7.2 稳定性验收

- 在正常测试环境下，事件上传成功率不低于 95%
- 连续执行 20 次以上上传与查询闭环，系统无阻塞、无崩溃
- 异常请求不会导致服务崩溃，均能返回明确错误

### 7.3 文档一致性验收

- 实际接口路径、字段与 `docs/api-spec.md` 一致
- 测试范围覆盖 `docs/requirements.md` 中 V1 必做功能
- 所有未决点均保留“待确认”标识，不以实现猜测替代正式定义

## 9. 待确认项

- 是否需要专门的设备注册与配网测试
- VAD 触发阈值、录音时长与去抖策略
- 图片与音频的最终大小上限
- 云端分析完成时延的验收阈值
- 弱网重试次数、退避策略与超时阈值
- 语音播报链路的降级策略与失败重试策略
- 是否需要补充安全测试，如重放攻击、签名过期、越权访问
