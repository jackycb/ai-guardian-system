# AI 看护系统门口看护器 V1 架构说明

## 1. 说明

本文描述门口看护器 V1 的总体架构、分层职责、关键模块划分与典型事件链路，供设备端、后端与 AI 集成实现参考。文档以 V1 最小闭环为目标，强调可实现性、可测试性与工程边界。

## 3. 分层说明

### 3.1 设备端

设备端负责事件触发、数据采集、事件组装、网络上传、结果轮询与本地反馈。

V1 涉及的主要硬件如下：

- Seeed XIAO Sense
- Seeed Mini PIR motion sensor
- MAX98357A + 3W 喇叭

设备端不承担复杂 AI 推理，重点在于稳定触发、可靠采集、可恢复上传和结果播报。

### 3.2 通信层

通信层负责设备与云端之间的 HTTPS 通信、鉴权、限流、基础日志与入口路由。

V1 默认只定义 HTTP API，不引入 MQTT、WebSocket 或推送回调。若后续扩展，需要另行设计，当前为“待确认”。

### 3.3 云端后端

云端后端负责接收设备上传请求、校验参数、保存事件、发起异步分析任务、提供结果查询接口与状态管理。

后端需要保证：

- 上传接口幂等策略可扩展
- 事件状态流转清晰
- 异常路径可观测
- 结果查询简单稳定

### 3.4 AI 调用层

AI 调用层负责将图像、音频与事件上下文送入模型或分析服务，得到标准化结果输出。

V1 的 AI 调用层主要负责：

- 组织输入数据
- 调用模型或分析服务
- 归一化输出字段
- 生成风险等级、摘要与建议播报文本

具体模型供应方、提示词结构与多模态调用方式：待确认。

### 3.5 存储层

存储层负责保存原始文件、事件元数据、分析结果与链路日志。

V1 建议拆分为：

- 对象存储：保存图片、音频
- 事件数据库：保存事件元数据和状态
- 结果数据库：保存分析结果和播报文本
- 日志存储：保存请求日志、错误日志、任务日志

具体阿里云产品选型：待确认。

### 3.6 反馈层

反馈层负责把云端结果转换为设备可播放的信息，并驱动本地语音播报。

V1 默认采用：

- 设备轮询结果接口
- 云端返回 `voice_broadcast_text`
- 设备本地完成最终播报

播报方式是固定短语、设备侧 TTS，还是云端下发音频：待确认。

## 4. 每层职责

| 层级 | 核心职责 |
| --- | --- |
| 设备端 | 触发检测、拍照、录音、事件打包、上传、轮询、播报 |
| 通信层 | HTTPS 接入、鉴权、路由、限流、请求日志 |
| 云端后端 | 参数校验、事件落库、状态管理、异步任务编排、结果查询 |
| AI 调用层 | 多模态输入处理、模型调用、结果归一化、风险评分、播报文本生成 |
| 存储层 | 原始文件保存、事件元数据保存、分析结果保存、日志保存 |
| 反馈层 | 查询结果、提取播报信息、本地音频输出 |

## 5. 关键模块划分

### 5.1 设备端模块

- `trigger_manager`
  - 统一接入 PIR 与 VAD 触发
  - 负责去抖、触发合并与采集启动
- `capture_manager`
  - 负责拍照和录音
  - 生成本地临时文件或内存缓冲
- `event_builder`
  - 组装 `device_id`、`event_type`、`trigger_source`、`sensor_payload`、`vad_payload`
  - 附带图片和音频文件
- `network_client`
  - 健康检查、上传事件、查询结果
  - 处理超时、重试与错误分类
- `result_poller`
  - 基于 `event_id` 轮询查询结果
  - 识别 `queued`、`processing`、`done`、`failed`
- `feedback_player`
  - 接收播报文本
  - 驱动 MAX98357A + 3W 喇叭播放

### 5.2 云端后端模块

- `health_controller`
  - 健康检查接口
- `device_event_controller`
  - 上传接口与结果查询接口
- `event_service`
  - 参数校验、事件创建、状态更新
- `storage_service`
  - 文件写入对象存储
  - 元数据写入数据库
- `analysis_orchestrator`
  - 异步调度 AI 分析任务
- `result_service`
  - 整理结果输出格式
  - 返回风险等级、摘要和播报文本

### 5.3 AI 调用层模块

- `input_adapter`
  - 将图片、音频与事件上下文转换为分析输入
- `model_gateway`
  - 封装模型调用
- `result_normalizer`
  - 统一输出字段
- `broadcast_text_builder`
  - 生成适合设备播报的文本

## 7. 实现建议

### 7.1 V1 实现原则

- 先实现单设备、单事件、单结果的稳定闭环
- 先采用同步上传 + 异步分析 + 轮询查询
- 先返回结构化结果和播报文本，不要求复杂消息通道
- 先保证日志与状态可见，再优化性能

### 7.2 工程边界

- 设备端实现关注状态机、错误恢复与资源管理
- 后端实现关注接口稳定性、状态一致性与任务编排
- AI 层实现关注统一输入输出，不把模型细节泄漏到设备端

## 8. 待确认项

- VAD 在设备端的具体实现方式
- 云端分析任务是消息队列驱动还是进程内异步任务
- 阿里云对象存储、数据库、日志方案的具体选型
- 语音播报是设备侧 TTS 还是云端下发音频
- 设备端本地缓存策略和离线补传策略
