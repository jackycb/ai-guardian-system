# AI 看护系统门口看护器 V1 需求说明

## 1. 项目概述

### 1.1 项目目标

本项目旨在构建一个基于 Seeed XIAO Sense 设备端与阿里云后端的 AI 看护系统 V1，首个落地场景为“门口看护器”。设备端基于红外感应与语音 VAD 触发拍照和录音，通过 WiFi 上传至阿里云后端，由云端完成事件存储、AI 分析与结果返回，设备再通过喇叭进行语音播报，形成完整的门口看护闭环。

### 1.2 V1 定位

V1 的目标不是做完整安防平台，而是验证以下闭环是否成立：

- 设备可以基于 PIR 红外和语音 VAD 稳定触发事件
- 设备可以完成拍照、短时录音并联网上传
- 云端可以接收事件并完成基础 AI 分析
- 分析结果可以被设备查询并用于本地语音播报
- 系统具备最基本的可观测性与可测试性

### 1.3 当前硬件基线

当前 V1 默认基于以下硬件组合设计：

- 主控与视觉模组：Seeed XIAO Sense
- 音频播放模块：MAX98357A + 3W 喇叭
- 人体感应模块：Seeed Mini PIR motion sensor

以下能力目前明确存在依赖但实现细节待确认：

- 语音输入采集链路
- VAD 的具体实现位置，是板端还是外部模块，待确认
- 摄像头、麦克风的最终驱动与参数配置，待确认

## 2. 使用场景

### 2.1 核心场景

- PIR 检测到门口有人经过或停留时，设备触发拍照
- 设备检测到语音 VAD 触发时，开始录制短音频片段
- 单次事件可同时包含图像、音频与传感器状态
- 设备通过 WiFi 将事件上传至阿里云后端
- 云端对事件进行 AI 分析，输出事件类型、风险等级、摘要说明与建议播报文本
- 设备接收分析结果后，通过喇叭进行语音播报

### 2.2 典型事件

- 门口有人经过
- 有人在门口停留超过阈值
- 夜间门口出现移动目标
- 检测到有人说话、呼叫、敲门或异常音量
- PIR 红外触发门口移动事件
- VAD 检测到有效语音片段

### 2.3 目标用户

- 独居老人家庭
- 有门口看护需求的家庭用户
- 后续可扩展到看护服务提供方或物业场景

## 3. 功能范围

### 3.1 V1 必做功能

- 设备身份标识与基础鉴权
- 设备健康检查接口联通验证
- PIR 红外触发事件采集
- 语音 VAD 触发录音采集
- 触发后进行拍照与短音频录制
- 设备上传事件元数据
- 设备上传图像与音频附件
- 云端接收事件并生成唯一 `event_id`
- 云端对事件执行异步 AI 分析
- 设备按 `event_id` 查询分析结果
- 分析结果至少包含处理状态、事件分类、风险等级、摘要和播报文本
- 设备可根据分析结果进行本地语音播报
- 后端记录请求日志、错误日志与关键链路状态

### 3.2 V1 建议功能

- 事件去重或幂等处理
- 上传失败后的设备端重试
- 云端分析超时状态标记
- 设备时间戳与服务端接收时间双记录
- 语音播报内容分级，如普通提示与告警提示
- PIR 和 VAD 去抖与误触发过滤

### 3.3 数据范围

V1 中单次事件建议至少支持以下数据：

- `device_id`
- `event_type`
- `trigger_source`
- `captured_at`
- `image`
- `audio`
- `sensor_payload`，可选
- `vad_payload`，可选
- `firmware_version`
- `request_id` 或 `sequence_id`，用于追踪，待确认

## 4. 非目标

以下内容不纳入门口看护器 V1 交付范围：

- 实时视频流推流与直播监看
- 双向语音对讲
- 连续对话式语音助手
- App 完整产品化能力
- 多设备分组管理平台
- 大规模设备 OTA 升级系统
- 复杂家庭自动化联动
- 高精度人脸识别、身份实名识别
- 长期录像存储与回放系统
- 计费、订阅、运营后台

## 5. 关键约束

### 5.1 设备侧约束

- 硬件平台为 Seeed XIAO Sense，算力、内存、存储空间有限
- 设备侧以轻量事件采集、基础触发控制、上传和播报为主，不承担复杂 AI 推理
- 音频播放通过 MAX98357A + 3W 喇叭完成
- 事件触发依赖 Seeed Mini PIR motion sensor 与 VAD 能力，需考虑误触发、漏触发和去抖策略
- 通过 WiFi 联网，需考虑弱网、断网、重连和抖动
- 供电方式、持续工作时长、低功耗策略：待确认
- 语音播报方式可为本地固定语音、设备侧 TTS 或云端返回文本后本地播报，最终方案待确认

### 5.2 云端约束

- 后端部署在阿里云体系内
- V1 优先保证简单、稳定、可观测，不追求高并发极限
- AI 分析流程允许异步完成，不要求同步返回最终结果
- 对象存储、数据库、消息队列等具体云产品选型：待确认
- 云端是否直接生成播报音频，还是仅返回播报文本：待确认

### 5.3 安全与合规约束

- 所有设备到云端通信应使用 HTTPS
- 设备需要具备基础鉴权能力，鉴权方案可为设备密钥、Token 或签名，具体方式待确认
- 涉及图像、音频数据，需考虑隐私保护与访问控制
- 语音播报需避免直接播报敏感个人信息，播报策略待确认
- 数据保留周期、脱敏策略、审计要求：待确认

### 5.4 交付约束

- 当前目标为门口看护器 V1 单场景闭环
- 优先定义触发条件、接口、事件流和验收口径，允许实现先简单后增强
- 未确认项需在文档中显式标注“待确认”，避免假设被误认为结论

## 6. 成功标准

### 6.1 业务成功标准

- 门口触发事件后，系统能够形成“触发 -> 拍照/录音 -> 上传 -> 分析 -> 返回结果 -> 语音播报”的完整闭环
- V1 可以覆盖门口看护的核心事件检测、结果反馈与本地提醒需求
- 项目团队可基于 V1 文档启动设备端、后端与测试实施

### 6.2 技术成功标准

- 设备可稳定调用健康检查接口
- PIR 和 VAD 触发后可正确进入采集流程
- 设备事件上传成功率达到 95% 以上，测试环境口径
- 云端成功为每个有效事件生成唯一 `event_id`
- 80% 以上正常事件可在目标时延内返回分析结果，目标时延阈值待确认
- 设备在获取分析结果后可完成一次有效语音播报
- 对非法请求、缺失字段、超大文件、鉴权失败等异常情况有明确定义与可观测日志

### 6.3 交付成功标准

- `docs/requirements.md`、`docs/api-spec.md`、`docs/test-plan.md` 三份文档内容完整且互相一致
- V1 必要接口、测试项与验收标准均已明确
- 所有关键不确定项均以“待确认”标记，无隐含决策

## 7. 待确认项

- VAD 的具体实现方式与阈值设置
- 音频录制时长、采样率与编码格式
- 设备上传图像的数量上限与分辨率要求
- 门口事件分类枚举及风险等级分级标准
- 结果返回方式是否只支持轮询，是否需要服务端主动推送
- 语音播报是播放固定短语、云端返回文本后本地 TTS，还是云端下发音频
- 设备鉴权机制与密钥下发方式
- 单次事件端到端时延目标
- 云端数据留存周期与存储成本约束
- 是否需要配套移动端、Web 端或仅设备联调即可
